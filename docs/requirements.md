# letsgetmarried 개발 기준

## 현재 확정 사항 (2026-10-21)

- 오성현·정지윤 두 사람의 비공개 결혼 준비 웹사이트.
- 결혼식: 2027년 9월 25일 토요일 14:00, Asia/Seoul.
- Next.js + Neon PostgreSQL + Vercel Hobby. 로컬 완성을 기다리지 않고 배포하는 현재 방침을 따른다.
- 로그인은 두 고정 아이디와 비밀번호. Neon Auth와 Google OAuth는 사용하지 않는다.
- 이름은 letsgetmarried, Pretendard, 로즈 블러시, 연결된 두 반지 로고.

## 세 가지 메뉴

### 일정

날짜순 목록이 기본이다. 각 일정의 날짜·시간·장소·메모·준비물·참고 자료를 본문에 표시하고 세로 스크롤로 확인한다. 일정은 제목만으로 추가할 수 있고 날짜·시간·장소는 나중에 입력한다. 완료와 준비물은 한 번의 체크로 저장한다. 준비물 추가·수정과 기본 체크리스트 불러오기도 일정 안에서 처리한다.

### 결정할 것

빠른 기록과 결정을 하나의 목록으로 합친다. 제목을 한 줄로 입력하고 미정·진행 중·완료로 관리한다. 모든 하위 결정을 상위 항목 바로 아래에 펼쳐 표시하고 제목·상태·정한 내용·메모를 그 자리에서 수정한다. 후보 이름·견적·조건과 참고 자료도 본문에 표시한다. 깊은 단계는 경로를 표시하고 들여쓰기 폭을 제한한다. 하위 결정은 각 상위 항목에서 바로 추가한다. 검색은 메모·후보·자료 이름을 포함하며, 검색·상태 필터에 맞는 하위 항목의 상위 경로는 간결하게 함께 표시한다.

### 예산

초기 목표 30,000,000원, 결혼 준비·본식 범위. 신혼여행은 기본 제외이며 범위를 수정할 수 있다. 목표·범위·분류 변경은 즉시 적용한다.

지출은 예상·확정·지급 완료로 직접 지정한다. 총금액과 이미 지급한 금액을 기록하고 남은 금액을 계산한다. ‘지급 완료’를 선택하면 전액 지급으로 저장한다. 계약금과 잔금은 같은 계약 총액 안에서 한 번만 집계한다. 후보 견적은 자동 합산하지 않는다. 결제 예정일은 선택 입력이며 30일 내 예정 금액을 확인할 수 있다. 개인별 분담·정산·하객 관리는 추가하지 않는다.

목표 예산·범위·분류별 합계와 각 지출의 금액·결제일·계약 내용을 기본으로 펼쳐 표시한다. 분류 이름과 예산 포함 여부도 본문에서 바로 수정한다. 전액 지급된 계약의 총액을 늘릴 때 기존 지급액을 유지하고 차액은 미지급으로 남긴다.

## 제거한 절차

의견 작성, 두 사람 동의, 동의 대기, 핵심 조건 변경 후 재동의, 예산 변경 제안을 제거한다. 누구나 자신의 계정으로 바로 기록을 추가·수정·완료할 수 있다. 로그인·권한 확인·동시 수정 충돌 검사는 유지한다.

## 참고 자료 반영

`references/`의 시농리 체크리스트, 행복만하기 준비표(빈 양식과 예시), 지출 CSV, 본식 준비 PDF/RTF, 축의대 안내를 검토했다. Planning.Wedding의 체크리스트·일정·예산 분리도 참고했다: https://planning.wedding/ko

- 반복되는 준비 항목을 16개의 선택형 템플릿으로 정리.
- 드레스 피팅·본식 전날·본식 당일·예식 후 준비물을 일정 체크리스트로 제공.
- 비용의 총액·지급액·남은 금액, 결제 예정일을 반영.
- 참고 파일의 업체명·금액·날짜·하객 명단은 실제 데이터로 가져오지 않음.
- 원본 참고 파일은 로컬에서만 보관하고 Git에 포함하지 않음.

## 기존 데이터

배포 마이그레이션에서 기존 workspace 전체를 한 번 백업한다. 스키마 1→2 변환은 반복해도 같은 결과여야 한다. 기존 일정·결정·후보·지출·자료·빠른 기록을 유지하고 이전 의견과 동의 데이터는 UI에 노출하지 않는다. 보류 중이던 예산 변경을 자동 적용하지 않는다. 합계와 각 지출 구간은 변환 전후 같아야 한다.

## 화면과 알림

PC에서는 상단 세 탭, 아이폰에서는 하단 세 탭을 유지한다. 일정·결정할 것·예산을 하나의 페이지로 합치지 않는다. 각 탭에서는 모든 세부 내용을 기본 노출하고 본문에서 수정한다. 내용이 없는 선택 항목은 추가 버튼으로 표시한다. 새 일정·지출·자료 추가와 설정·삭제 확인에만 별도 창을 사용한다. 검색·필터·목차는 스크롤 중에도 접근할 수 있고, 저장 후 위치 및 탭별 스크롤 위치를 유지한다. 예식일 디데이는 한국 날짜 기준이다. 키보드 탐색, 44px 터치 영역, 모션 감소 설정을 지원한다.

체크·선택은 즉시 저장하고 글·금액은 입력란을 벗어나면 자동 저장한다. 저장 요청은 순서대로 처리하고, 각 수정은 마지막 저장 결과에 합쳐 기존 버전 검사를 유지한다. 다른 필드의 공동 수정은 최신 기록을 읽어 반영하고, 같은 필드의 충돌은 내 입력과 최신 내용을 표시해 사용자가 선택한다. 저장 실패 입력은 탭·검색 전환 중에도 메모리에 유지하며 재시도할 수 있다. 저장하지 못한 입력이 있는 상태에서 페이지를 떠나면 브라우저 경고를 제공한다. 실패한 입력이 새로고침 후에도 보존된다고 보장하지 않는다.

일정 알림은 동의 여부와 관계없이 날짜가 있고 미완료·미보관인 일정에 적용한다. iPhone PWA 설치와 실제 푸시 수신은 기기에서 검증한다. 파일 첨부는 비공개 저장소가 연결된 경우에만 노출한다.
