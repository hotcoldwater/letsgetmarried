## 작업 순서

요구사항 합의 → 디자인 후보 비교 → 사용자 선택 → 로컬 구현 → PC·아이폰 검증 → 로컬 완성본 확인 → 배포.

로컬 완성 전 공개 배포나 프리뷰 배포를 하지 않는다. 사용자가 타임라인 A · 예산 B · Pretendard · 로즈 블러시를 최종 선택했다. 디자인 기준과 외부 디자인 도구용 최종 프롬프트를 확정했으며, 이후 로컬에서 제품 기능을 구현하고 검증한다.

시안용 로컬 HTML과 별도로 Next.js 실사용 앱 소스를 작성했다. Neon 로그인·서버 저장·공동 동의·일정·예산·자료·푸시 코드는 연결 검증 전이다. Node.js 및 Neon 설정 후 패키지 설치, 빌드, DB/OAuth/실제 아이폰 테스트를 진행한다. 상세한 현재 상태와 작업 순서는 README 및 `neon-setup.md`에 기록한다.

## 예산

- 초기 목표 30,000,000원. 초기 범위는 결혼 준비·결혼식까지.
- 목표 금액, 범위, 항목, 분류를 추후 편집할 수 있게 한다.
- 신혼여행은 타임라인에는 표시할 수 있으나 초기 예산에서 제외.
- 공동 결혼식 계좌 기준 지출. 개인별 분담, 결제자 관리, 자동 정산은 첫 버전에서 제외.
- 계약금·잔금 부분 지급을 지원. 실제 지급 기록은 한 사람이 추가할 수 있다.
- 합계 = 지급 완료 + 확정 미지급 + 미확정 예상. 같은 비용을 중복 합산하지 않는다.
- 미선택 후보 견적, 패키지와 구성 항목을 중복 합산하지 않는다. 미입력과 0원을 구분.
- 선택 확정: B안, 수평 누적 막대와 목표 예산선. 초과 금액을 잘라 표시하지 않는다.

## 기록과 공동 결정

- 예식장·스드메·청첩장·예복 등의 기본 항목을 제공하고 자유롭게 수정·추가·삭제.
- 제목만으로 미정리함에 빠르게 기록. 나중에 분류하거나 기존 항목에 연결.
- 준비 항목 → 질문 → 후보·하위 질문 구조를 계속 추가할 수 있어야 한다.
- 준비 항목, 질문, 후보별 코멘트와 선택 이유, 변경 이력.
- 두 사람이 같은 선택에 모두 동의해야 확정. 한 명만 동의하면 상대 동의 대기.
- 선택이나 핵심 계약 조건이 바뀌면 재동의. 코멘트·자료 추가는 동의를 초기화하지 않는다.
- 결정 완료, 일정 수행 완료, 지출 완료는 별도의 상태.

## 일정과 자료

- 선택 확정: A안, 준비 시작부터 결혼식·신혼여행까지 중요한 순간을 연결하는 수평 타임라인. 점 간격은 시간 비례가 아닌 순서 중심임을 안내.
- 하나의 준비 항목에 촬영·피팅 등 여러 일정을 연결.
- 일정 등록과 예산 포함 여부는 독립적.
- PC: 전체 흐름과 상세 내용. 모바일: 가까운 일정 목록 기본, 전체 수평 타임라인 펼침.
- 날짜 미정 목록을 유지.
- 사진·이미지·PDF·링크 첨부는 첫 버전 포함. 아이폰 사진 추가·미리보기 지원.
- 두 사람만 접근 가능한 자료 보관, 이미지 용량 관리.

## 아이폰과 알림

- 홈 화면에 추가하는 PWA. 사이트 내부 알림 + 웹 푸시.
- 새 코멘트, 동의 요청, 결정 확정, 일정 알림. 종류·시점은 개인별 설정.
- 알림에서 관련 항목으로 이동. 푸시 거부 시에도 사이트 내부 알림 유지.
- 배포 후 예약 알림은 사용자 PC가 꺼져 있어도 서버에서 발송.
- iOS 16.4 이상 홈 화면 웹앱의 사용자 허용 조건을 고려.
- 실제 아이폰 푸시 로컬 검증에는 신뢰되는 로컬 HTTPS 환경 필요. 배포 주소에서도 재검증.
- 이번 PC 크기 전환 시안은 실제 아이폰 하드웨어 검증이 아니다.
