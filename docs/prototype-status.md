# letsgetmarried

두 사람을 위한 결혼 준비 플랫폼. **로즈 블러시 · 타임라인 A · 예산 B · Pretendard**를 기준으로, 사용자가 제공한 Stitch 모바일·PC 4개 화면을 하나의 반응형 로컬 프로토타입으로 통합했습니다.

## 로컬에서 보기

패키지 설치 없이 `studio.html`을 Chrome에서 열면 PC, 393px, 375px 화면을 비교할 수 있습니다. `index.html`은 앱 화면을 직접 엽니다.

로컬 서버를 사용할 수 있는 환경에서는 다음 명령으로 실행할 수도 있습니다.

```sh
cd /Users/david/projects/letsgetmarried
python3 -m http.server 4173 --bind 127.0.0.1
```

이후 `http://127.0.0.1:4173/studio.html`을 엽니다. 이번 작업 환경에서는 서버 포트 열기가 제한되어 Chrome의 로컬 파일 방식으로 확인했습니다.

## 현재 동작하는 기능

- 타임라인: PC 수평 마일스톤, 모바일 전체 여정 펼침, 완료 항목 숨기기, 예시 일정 상세.
- 체크리스트: 완료 상태와 진행률 갱신, 브라우저 저장.
- 빠른 기록: 제목 입력, 완료 표시, 삭제와 10초간 되돌리기, 브라우저 저장.
- 예산: 목표 금액·범위 설명 수정, 지출/견적 추가 및 수정, 부분 지급, 상태별 합계와 항목별 표·카드.
- 예산 초과 시안: 예식장 예상액에 400만 원을 임시 추가. 저장된 데이터에는 영향을 주지 않음.
- 결정 보관함: 예시 질문과 후보 살펴보기, 로컬 의견 기록.
- Pretendard 폰트·아이콘·스타일을 로컬 파일로 제공. 외부 Tailwind 런타임이나 Google 폰트 요청 없음.

기록은 `localStorage`의 `letsgetmarried-local-prototype-v1` 키에 저장됩니다. 이 브라우저에서만 유지되며 파트너와 공유되지 않습니다. 브라우저 데이터 삭제 시 사라집니다. 로컬 파일과 로컬 서버 주소의 저장 공간은 서로 다를 수 있습니다. 저장을 사용할 수 없거나 기존 데이터 형식이 맞지 않으면 원본을 덮어쓰지 않고 임시 사용임을 화면에 표시합니다.

예산의 범위 입력은 설명 수정입니다. 범위별 비용 포함/제외나 분류 추가·삭제 기능은 아직 구현하지 않았습니다. 기존 견적이 확정되면 **기존 기록을 수정**해 상태를 변경합니다. 같은 계약을 다시 추가하면 별도 비용으로 계산됩니다.

## 예시와 계산 기준

신랑 **오성현**, 신부 **정지윤**. 결혼식은 **2027년 9월 25일 토요일 14:00**입니다. 이 정보는 `model.js`의 `wedding`에 한 곳에서 관리하며, 디데이는 한국 시간의 오늘 날짜를 기준으로 계산합니다. 예식 장소와 신혼여행 출발일은 미등록입니다. 다른 준비 일정·동의 상태·초기 지출 금액은 예시입니다.

이전 저장 데이터의 예시 결혼식 날짜는 새 정보에 영향을 주지 않습니다. 기존 예산·기록·체크리스트·의견을 유지해 새 형식으로 읽으며, 다음 저장 시 같은 키에 갱신됩니다. 이전 색감 비교 화면은 당시의 예시를 보존한 디자인 기록입니다.

| 상태 | 지급 완료 | 확정 미지급 | 미확정 예상 | 최종 예상 | 예산과의 차이 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기본 | 820만 | 1,260만 | 760만 | 2,840만 | 160만 여유 |
| 예상 +400만 | 820만 | 1,260만 | 1,160만 | 3,240만 | 240만 초과 |

막대·목표선·범례·표는 같은 금액 모델에서 계산합니다. 초과 구간은 기존 막대 위의 무늬로 표시하며 별도 지출로 합산하지 않습니다. 확정 계약의 미지급액은 총금액에서 지급액을 뺀 값입니다. 빈 금액 입력은 저장하지 않고 실제 0원 입력과 구분합니다.

## 검증

- 예산 합계, 부분 지급, 상태 전환, 표·막대 일치, 입력 검증, 저장 데이터 검증 **48개 통과**.
- 한국 시간 자정 전후 디데이 및 기존 기록 보존 검증 **17개 통과**.
- JavaScriptCore에서 JavaScript 구문 검증 통과.
- Chrome PC 및 393px·375px 미리보기에서 화면 배치 확인.
- 실제 UI에서 빠른 기록의 특수문자 표시와 새로고침 후 유지, 삭제, 체크리스트, 완료 일정 필터, 모바일 여정 펼침, 초과 시안, 지출 폼의 과다 지급액 차단 확인.
- 실제 아이폰 Safari·홈 화면 웹앱·푸시는 아직 검증하지 않음.

Node가 설치된 환경에서 계산 검증을 실행할 수 있습니다.

```sh
node scripts/check-model.js
node scripts/check-wedding.js
```

## 파일

- `index.html`, `app.css`, `app.js`: 통합 앱 화면과 로컬 상호작용.
- `model.js`: 예시 데이터, 예산 계산, 입력·저장 데이터 검증.
- `studio.html`, `studio.js`: PC·아이폰 크기 비교.
- `scripts/check-model.js`: 계산 및 데이터 검증.
- `scripts/check-wedding.js`: 한국 시간의 날짜 경계와 기존 저장 데이터 보존 검증.
- `design-review.html`, `review.css`, `review.js`: 이전 색감 비교와 확정 프롬프트 복사.
- `preview.html`, `preview.css`, `preview.js`, `themes.css`, `preview-theme.css`: 이전 디자인 후보 기록.
- `fonts.css`, `assets/fonts/`: Pretendard Variable 1.309 및 OFL 라이선스.
- `design-brief.js`, `docs/design-prompts.md`: 외부 디자인 도구용 프롬프트.
- `docs/requirements.md`: 합의한 전체 제품 요구사항.
- `docs/stitch-integration.md`: 시안 통합 과정에서 바로잡은 사항과 구현 범위.
