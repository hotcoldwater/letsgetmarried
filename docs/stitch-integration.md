# Stitch 시안 통합 기록

2026-10-17. 사용자가 전달한 모바일 예산, 모바일 타임라인, PC 타임라인, PC 예산 HTML을 디자인 기준으로 반영했습니다. 네 개 문서를 그대로 이어 붙이지 않고 화면 크기에 따라 같은 데이터를 다르게 배치하는 로컬 프로토타입을 구성했습니다.

## 유지한 디자인

- 로즈 블러시 배경, 짙은 로즈 포인트, 밝은 카드, 얇은 경계와 절제된 그림자.
- PC 상단 메뉴, 모바일 하단 메뉴, 날짜 요약 카드, 수평 마일스톤.
- PC의 일정·빠른 기록 2열 구성, 모바일의 한 열 카드 구성.
- 예산 누적 막대, 목표선, 세 상태의 범례, PC 표·모바일 항목별 카드.
- 짧은 상태 전환 애니메이션. 지속적으로 깜박이는 효과는 제거하고 reduced-motion을 반영.

## 바로잡은 부분

| 제공된 코드 | 통합 후 |
| --- | --- |
| Plus Jakarta Sans | 한글·영문·숫자 모두 로컬 Pretendard |
| 각 화면의 별도 데이터와 서로 다른 이름 | 같은 모델 사용, ‘나 & 파트너’ 및 예시 표시 |
| 상단 합계와 상세 표 합계 불일치 | 모든 합계를 항목 데이터에서 계산 |
| 초과액을 네 번째 지출 막대로 추가 | 세 지출 상태만 합산, 실제 초과 영역에 무늬 표시 |
| 목표선과 지출 막대의 축척 불일치 | 하나의 금액 축을 공유, 큰 초과 시 축 자동 확장 |
| +400만 시나리오를 400만 초과로 표기 | 기존 여유 160만을 반영해 240만 초과 표시 |
| 전체 예상액을 ‘소진율’로 표현 | ‘예산 대비 예상’과 ‘실제 지급’을 별도 표시 |
| 미집행 0원을 총비용 0원 확정으로 표현 | 해당 상태의 금액이 0임을 명확히 표시 |
| 상대방 이름으로 동의하는 버튼 | 실제 계정 연결 전에는 예시 상태만 표시 |
| 접속 중·동기화 완료·푸시 발송 단정 | 브라우저 로컬 저장 및 미연결 상태 안내 |
| 모바일 전체 타임라인 기본 펼침 | 가까운 일정 목록과 전체 여정 펼침 버튼 |
| ‘완료 숨기기’가 투명도만 변경 | 완료 노드를 실제로 제외 |
| 입력값을 그대로 HTML에 삽입 | 사용자 입력을 이스케이프해 문자열로 표시 |
| 모바일 확대 차단 | 일반 viewport와 확대 허용 |
| 토스트만 나타나는 지출 기록 버튼 | 금액·분류·상태·부분 지급 입력 및 로컬 저장 |

초기 항목별 총액과 상단 상태별 합계를 유지하기 위해, 서로 모순되던 세부 상태별 예시 금액을 재구성했습니다. 실제 사용자의 계약이나 지출을 수정한 것이 아닙니다. 예식장 1,750만, 스드메 540만, 예복·예물 250만, 청첩장·답례품 150만, 기타 150만으로 합계 2,840만입니다.

## 구현과 검증 범위

브라우저 저장은 빠른 기록, 피팅 체크리스트, 예산 목표·범위 설명, 비용 기록, 예시 결정에 남긴 의견에 적용했습니다. 공동 결정과 일정은 아직 예시 구조입니다. 후보 견적과 패키지 구성의 자동 중복 제거, 전체 준비 항목 편집, 첨부, 권한, 알림은 추후 제품 구현 범위입니다.

계산과 저장 데이터 검증 48개가 통과했습니다. Chrome의 데스크톱·393px·375px 미리보기, 예산 초과 전환, 특수문자가 포함된 기록의 저장·재로드·삭제, 체크리스트 갱신, 완료 일정 숨김, 모바일 전체 여정 펼침, 지출 폼에서 총금액보다 큰 지급액 저장 차단을 확인했습니다. 검증용 기록은 정리하고 체크리스트는 기본 상태로 복원했습니다.

화면 크기 미리보기는 실제 iPhone/Safari 검증이 아닙니다. 서버 포트를 열 수 없는 작업 환경이라 로컬 파일로 확인했으며 실제 아이폰 HTTPS·PWA·푸시, Supabase 연결, 배포는 진행하지 않았습니다.
