# 로즈 블러시 최종 디자인 요청 프롬프트

확정: **로즈 블러시 · 타임라인 A · 예산 B · 전체 Pretendard**.

아래 코드 블록 전체를 Stitch 등 디자인 생성 도구에 전달한다. 로컬 화면의 **확정 프롬프트 복사**도 같은 내용을 제공한다. 다른 색감을 비교 중이어도 복사 내용은 최종 확정안을 유지한다.

## 최종 프롬프트

```text
[최종 확정 디자인]
로즈 블러시 · 타임라인 A · 예산 B · 전체 Pretendard. 사용자 선택이 끝난 디자인이므로 이 조합을 유지하고 세부 화면을 발전시킨다.

당신은 한국어 서비스의 반응형 제품 디자이너다. “우리의 결혼 준비”라는 두 사람 전용 비공개 웹앱을 디자인하라. 결혼을 준비하는 두 사람이 일정, 예산, 여러 단계의 결정, 사진과 의견을 함께 관리한다. 한 명은 PC, 다른 한 명은 아이폰을 주로 사용하며 두 사람 모두 아이폰이다.

[이번 요청의 범위]
로그인 후 사용하는 실제 제품 화면의 디자인 시안을 만든다. 이미 정한 정보 구조와 예시 데이터는 유지한다. 첫 결과는 타임라인과 예산 화면의 PC 1440px·아이폰 393px 버전, 총 4개 화면이다. 모바일 375px에서도 가로 넘침 없이 읽혀야 한다. 그 후 같은 디자인 시스템으로 준비 항목 상세와 빠른 기록 화면을 확장한다. 소개용 랜딩 페이지, 요금제, 마케팅 히어로, 가상의 제품 리뷰는 넣지 않는다.

[확정한 디자인]
- 타임라인 A: “한 줄의 여정”. 중요한 순간을 하나의 수평선으로 연결하는 마일스톤 방식. 점 간격은 일정 순서 중심이며 실제 기간 비례가 아님을 안내한다. 날짜·제목·상태를 표시하고 누르면 관련 일정 상세를 연다.
- PC는 전체 여정과 다가오는 일정, 날짜 미정 항목을 함께 보여준다. 아이폰은 다가오는 일정 목록을 기본으로 보여주고 전체 수평 타임라인은 펼쳐서 가로 이동한다. 좁은 화면에 데스크톱을 축소해 넣지 않는다.
- 예산 B: “한눈에 예산 바”. 수평 누적 막대와 별도의 목표 예산선. 지급 완료 → 확정 미지급 → 미확정 예상 순으로 쌓는다. 합계는 세 상태를 더한 최종 예상 지출이다. 같은 금액, 계약금과 잔금, 패키지와 구성 항목, 미선택 업체 견적을 중복 합산하지 않는다.
- 합계, 목표, 남음/초과 금액, 예산 대비 비율, 상태별 범례·금액과 항목별 표를 함께 보여준다. 초과분을 잘라내거나 100%에 가두지 않는다. 초과 경고는 문구와 별도의 적색으로 구분한다. 미입력과 0원을 구분한다.
- 제목, 본문, 버튼, 날짜, 금액, 영어, 차트까지 모두 Pretendard. 영문에 다른 세리프나 손글씨 폰트를 섞지 않는다. 글꼴을 도구에서 지원하지 않으면 이를 명시하고 내보내는 코드에 Pretendard를 지정한다.

[일관된 예시 데이터]
기준일 2026-11-14, 결혼식 2027-04-17. 실제 사용자 일정이 아닌 디자인용 예시다.
타임라인: 예식장 계약 2026-11-07 완료 / 드레스 첫 피팅 11-21 확정 / 스튜디오 촬영 12-12 확정 / 청첩장 주문 2027-02-06 동의 대기 / 결혼식 04-17 확정 / 신혼여행 출발 04-19 예정.
목표 예산 30,000,000원, 초기 범위는 결혼 준비·결혼식. 목표와 범위는 추후 편집 가능하다. 신혼여행은 일정에는 보이지만 초기 예산에서 제외한다.
정상: 지급 완료 8,200,000원 + 확정 미지급 12,600,000원 + 미확정 예상 7,600,000원 = 28,400,000원. 1,600,000원 남음, 94.7%.
초과: 미확정 예상만 11,600,000원으로 바꿔 합계 32,400,000원. 2,400,000원 초과, 108.0%.
표(항목 / 지급 완료 / 최종 예상, 단위 만 원): 예식장 500 / 1,750, 스드메 200 / 540, 예복·예물 100 / 250, 청첩장·답례품 20 / 150, 기타 준비 0 / 150. 초과 상태에서는 예식장 최종 예상만 2,150으로 바꾼다.

[다른 화면에 이어질 핵심 흐름]
- 제목만 입력해 미정리함에 빠르게 기록하고 나중에 분류한다. “스드메 → 올인원/개별 업체 → 업체 후보 → 드레스·촬영 콘셉트·헬퍼”처럼 질문과 후보, 하위 질문을 계속 추가한다.
- 질문·후보별 코멘트, 선택 이유, 사진·이미지·PDF·링크를 표시한다. 아이폰 사진 첨부를 고려한다.
- 같은 선택에 두 사람이 모두 동의해야 결정 확정. 0/2, 1/2 동의 대기, 2/2 확정 상태를 명확히 구분한다. 핵심 선택·계약 조건 변경 시 재동의, 코멘트·자료 추가만으로는 초기화하지 않는다. 결정 완료·일정 수행 완료·지출 완료는 서로 다른 상태다.
- 공동 계좌를 사용하므로 개인별 분담·결제자 정산 화면은 만들지 않는다. 계약금과 잔금의 부분 지급은 지원한다.
- 홈 화면에 추가한 아이폰 PWA를 고려한다. 내부 알림, 새 코멘트·동의 요청·결정 확정·일정 푸시의 개인별 설정과 허용 안내 화면을 후속으로 마련한다. 시안에서 실제 푸시가 구현됐다고 표시하지 않는다.

[분위기와 사용성]
청첩장의 정갈함, 부드러운 색, 넉넉한 여백, 얇은 선, 절제된 반지·리본·꽃잎 모티프로 결혼식의 느낌을 표현한다. 장식은 정보와 겹치지 않으며 큰 사진으로 주요 기능을 밀어내지 않는다. 지나친 그라데이션·유리 효과·반복 하트·스크롤 패럴랙스는 사용하지 않는다.
본문은 PC 14–16px, 모바일 15–16px를 기준으로 하고 보조 정보도 충분히 읽히게 한다. 일반 텍스트 대비 4.5:1 이상, 아이폰 터치 영역 최소 44px, 키보드 포커스, 색 이외의 상태 라벨을 마련한다. 숫자는 고정폭 숫자 기능을 사용해 비교하기 쉽게 한다.
카드와 상세 펼침은 180–240ms, 상태와 예산 변화는 250–400ms의 부드러운 전환을 제안한다. 무한 장식 애니메이션과 과한 바운스를 피하고 prefers-reduced-motion에서는 애니메이션을 생략한다.

[산출물]
1. 동일한 데이터와 정보 구조를 유지한 PC·아이폰 타임라인/예산 시안. 예산 초과 상태도 추가 제시.
2. 색상 HEX와 역할, Pretendard 크기·굵기·행간, 간격·모서리·버튼·상태 칩의 디자인 토큰.
3. 반응형 규칙과 화면별 구성 요소, 주요 상호작용 및 모션 명세.
4. 코드 내보내기를 지원하면 재사용 가능한 컴포넌트와 CSS 변수 중심 코드를 제공한다. 특정 유료 라이브러리에 의존하지 않는다. 백엔드·로그인·Supabase 연결과 배포는 이번 디자인 생성 범위에 넣지 않는다.

[이번 색감: 02 · 로즈 블러시]
장미 꽃잎과 옅은 분홍 청첩장의 로맨틱함. 더스티 로즈와 짙은 플럼으로 성숙하고 부드럽게. 핫핑크, 하트의 반복, 지나치게 귀여운 캐릭터는 피한다.
배경 #FCF7F7, 핵심 포인트·지급 완료 #945D72, 확정 미지급 #D7A8B9, 미확정 예상 #F1DCE5. 본문은 이 색감에 맞는 짙은 중성색을 사용하고, 밝은 차트 구간에는 어두운 글자를 사용한다. 지정 색상을 출발점으로 대비를 확보하되 팔레트의 분위기는 유지한다. 다른 색감과 비교할 때는 레이아웃·내용·폰트·차트 형태를 바꾸지 않는다.
```

## 후속 개선 요청

```text
확정한 로즈 블러시와 타임라인 A·예산 B 구성을 유지하라. PC와 아이폰에서 읽기 어려운 작은 글씨, 긴 제목 줄바꿈, 예산 초과 경고, 1/2 동의 대기, 날짜 미정, 사진 첨부 화면을 점검해 개선하라. 정보 구조를 바꾸지 말고 필요한 수정 이유를 설명하라. Pretendard 이외의 글꼴을 사용하지 마라.
```
