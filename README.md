## 기능

- **일정 표:** 일정 이름·카테고리·날짜·시간·장소·완료·준비물 진행률·메모·자료를 한 행에 표시. 핵심 셀을 눌러 수정하고, 메모·준비물·자료는 해당 행 아래에서 펼쳐 관리.
- **결정할 것 표:** 카테고리·제목·상태·정한 내용·후보 수·메모·자료를 나란히 표시. 하위 결정은 들여쓰기로 구분하며 검색·카테고리·상태 필터에서도 상위 맥락을 유지. 후보 비교·견적·하위 결정 추가는 상세 행에서 제공.
- **공통 카테고리:** 일정과 결정할 것에서 같은 카테고리를 사용. 직접 추가·이름 변경·순서 변경 가능. 삭제할 때는 연결된 기록을 다른 카테고리 또는 미분류로 이동하고, 공통 자료가 있으면 다른 카테고리로 함께 이동. 기존 기록·보관 기록·하위 관계·지급액 보존.
- **검색·정렬:** 카테고리와 상태 필터, 제목·내용 검색을 함께 적용. 날짜·이름·상태·카테고리 순 정렬, 결정의 같은 단계 내 수동 순서 편집 지원. 탭을 오가도 각 탭의 필터·검색·정렬·표 스크롤 위치 유지. 필터에서 항목을 추가하면 해당 카테고리 자동 선택.
- **표 탐색:** 열 제목과 첫 항목명 열을 고정. 모바일에서도 좌우 스크롤로 열을 확인하고 상세는 화면 너비에 맞춰 표시. 예산은 대분류별 상세 목록 유지.
- **자동 저장:** 체크·선택은 즉시, 글·금액은 입력란을 벗어나면 저장. 요청을 순차 처리하고 최신 기록에 수정한 필드만 합침. 저장 상태·실패 재시도·같은 필드의 공동 수정 충돌 표시. 실패 입력은 탭 이동 중 유지하며 새로고침·페이지 종료 전에는 브라우저 경고 제공.
- **금액 입력:** 모든 탭의 견적·목표 예산·총금액·지급액과 추가 창에서 입력 중 천 단위 콤마 표시. 모바일 숫자 키패드, 콤마가 포함된 금액 붙여넣기, 중간 수정·삭제 지원. 금액은 숫자로 저장하며 빈 견적과 0원을 구분.
- **순서 편집:** 같은 단계의 결정들을 위·아래 버튼으로 이동하면 바로 저장. 하위 결정의 순서도 독립적으로 관리.
- 일정의 **메모와 준비물 개수**는 챙길 것의 내용 있는 줄, 기존 준비물, 입력 중인 새 준비물을 함께 표시.
- **준비 항목 불러오기 → 목록 이름·분류 수정**에서 기본 목록을 수정하고 저장. 선택 없이 문구만 저장할 수 있으며, 이미 추가한 결정의 내용은 유지.
- 일정·결정·지출·후보·자료 삭제 지원. 상위 결정 삭제 시 하위 결정도 삭제하며 연결된 지출 금액은 유지.
- **예산:** 목표 3천만 원에서 시작. 대분류 아래에 세부항목을 펼쳐 표시하고 해당 분류에서 바로 추가. 대분류별 총금액·지급액·남은 결제금액을 자동 집계하며 항목의 분류 이동 지원. 모바일에서는 금액을 세로로 배치. 전체 예산 여유/초과와 남은 결제금액을 구분하고 예상·확정·지급 완료와 부분 지급 지원. 전액 지급한 계약의 총액을 늘려도 지급액은 유지.
- 예산 검색은 대분류 이름·항목·메모·자료에 적용. 검색·상태 필터는 표시할 항목만 바꾸며 전체 예산 합계는 유지. 분류의 예산 포함 여부와 보관 처리에 따라 집계.
- 결제 예정일과 30일 내 예정 금액, 중복 없는 계약 총액·지급액 집계.
- 의견·동의·재동의·예산 변경 승인 절차를 제거. 빠른 기록은 결정할 것에 통합.
- 참고 자료에서 정리한 선택형 준비 항목 16개, 일정에 불러오는 준비물 체크리스트 4종.
- 비공개 사진/PDF 첨부는 별도 Object Storage 연결 시 제공. 링크 자료는 바로 이용 가능.
- 설정에서 기기별 Web Push. 미완료 일정 알림과 iPhone PWA.
- 동시 수정은 버전 조건 갱신으로 충돌 감지. 두 계정의 로그인과 기록 접근 제한은 유지.

## 기존 기록 호환

`db/004_simple_planner.sql`은 기존 기록 전체를 `wedding.workspace_backups`에 한 번 백업하고 JSON 스키마 1·2를 허용합니다. 기존 SQL 파일은 변경하지 않습니다. 기존 기록은 읽을 때 변환하고 다음 저장 시 버전 조건 갱신과 함께 스키마 2로 저장합니다.

확정 후보와 지출 분류·지급액을 유지하고, 빠른 기록은 같은 ID의 결정 항목으로 합칩니다. 이전 의견과 동의 데이터는 UI에서 제거하되 원본 데이터에 남깁니다. 대기 중이던 예산 제안은 자동 적용하지 않습니다. 로컬 `references/`의 원본, 예시 금액과 하객 정보는 Git이나 실제 공동 기록에 업로드하지 않습니다.

## 배포와 검증

Node.js 24에서 `npm test`와 `npm run build`를 실행합니다. 시안 모델 65개, 단순화·데이터 변환·예산·푸시·삭제·하위 결정·순서·준비 목록 규칙 147개, 아이디/비밀번호/토큰 검사 19개, 자동 저장·공동 수정·금액 입력·분류 이동 검사 20개, 공통 카테고리·표 필터·정렬·기록 보존 검사 9개, 실제 React 컴포넌트의 표·상세·저장 실패·추가 폼 렌더링 검사 5개로 총 265개입니다. 렌더링 검사는 Node에서 실행하며 브라우저나 실제 DB에 접속하지 않습니다. 최근 금액 입력·예산 분류·일정/결정 표 변경의 브라우저 실사용 검증은 로컬 서버 실행과 `file://` 접근 제한으로 완료하지 못했습니다. 실제 아이폰 푸시는 별도 검증이 필요합니다.

Vercel의 빌드는 환경 변수 검사 → DB 마이그레이션 → Next.js 빌드 순서입니다. 기존 공동 기록은 재배포해도 덮어쓰지 않습니다. `vercel.json`에 Singapore 리전과 하루 한 번 Cron을 지정했습니다.

## 로컬 개발 (선택)

```sh
npm ci
npm run setup:local
# .env.local에 APP_URL과 DATABASE_URL 입력
npm run doctor
npm run db:migrate
npm test
npm run build
npm run dev
```

`.env.local`과 비밀번호 설정 키는 Git에 포함하지 않습니다. 기존 `.env.local`을 사용하는 경우 GROOM_SETUP_TOKEN과 BRIDE_SETUP_TOKEN이 각각 32바이트 난수 base64url 값인지 확인하세요.

## 파일 구성

- app/: 실제 앱 화면과 API
- lib/: 도메인 규칙, 비밀번호 처리, 서버 연결
- db/: 버전별 SQL 마이그레이션
- public/: PWA 아이콘과 service worker
- scripts/: 설정 생성, 환경 점검, DB 초기화, 테스트
- docs/vercel-deploy.md: 현재 배포 절차
- index.html, studio.html, app.js, model.js: 이전 디자인 시안. 예시 데이터는 실제 DB에 이관되지 않음

이력 전체 내용 비교·복구, HEIC 변환, 이미지 확대 전용 화면은 후속 보완 대상입니다. 화면을 다시 열거나 새로고침하면 공동 기록을 갱신하며 실시간 스트리밍 방식은 아닙니다.
